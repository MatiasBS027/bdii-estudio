El log es la base de datos

Esa es la idea central de Aurora: el servicio relacional OLTP de AWS que desacopla cómputo y almacenamiento, escribe solo el redo log a un storage distribuido multi-AZ, y deja que el storage materialice páginas, recupere y se auto-repare — para escalar sin que la red colapse.

Esta app te lleva desde cero (¿por qué la red es el cuello de botella?) hasta los detalles finos (quórum 4/6, segmentos de 10GB, VCL/VDL, PGMRPL), con animaciones interactivas, guías paso a paso y un quiz con casos para comprobar lo que aprendiste.

Cómputo ≠ Almacenamiento

Cómputo = MySQL/InnoDB (queries, transacciones, locks, caché). Almacenamiento = servicio distribuido que guarda solo el log, materializa páginas y se recupera solo. Aurora los separa.

La idea central en 1 línea

Todo write es solo un redo log record con LSN. Las páginas nunca salen del engine: el storage las genera aplicando el log.
