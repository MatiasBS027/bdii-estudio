Google's Consistent, Global Authorization System

Apuntes de estudio · Basado en Zanzibar: Google's Consistent, Global Authorization System · Pang et al., USENIX ATC 2019

¿Puede este usuario hacer esto?

Esa es la única pregunta que responde Zanzibar. Es el sistema interno con el que Google decide —para Drive, Calendar, YouTube, Maps, Photos, Cloud y más— quién tiene permiso de ver, editar o compartir cada cosa, a escala global y de forma consistente.

Esta app te lleva desde cero (¿qué es una tupla?) hasta los detalles finos (zookies, TrueTime, Leopard), con animaciones interactivas, guías paso a paso y un quiz con casos para comprobar lo que aprendiste.

Autenticación ≠ Autorización

Autenticación = quién eres (login). Autorización = qué puedes hacer. Zanzibar solo hace lo segundo.

La idea central en 1 línea

Todo permiso se guarda como una tupla: objeto#relación@usuario. El resto son reglas para derivar más permisos.

Pulsa los botones y observa cómo se comporta el sistema. Estas son las mismas ideas de los módulos, pero en movimiento.

1 · El grafo de tuplas

Cada tupla es una arista dirigida entre objetos/usuarios. Añade tuplas y luego ejecuta un Check para ver el recorrido.

2 · Evaluación de un Check (árbol de decisión)

Zanzibar evalúa la relación viewer como una unión de ramas, en paralelo. Aquí se recorre paso a paso.

3 · El "new enemy problem"

¿Por qué la consistencia importa? Mira qué pasa si un Check lee datos atrasados después de que alguien fue removido.

4 · Ciclo de vida del zookie

El zookie es un token de frescura que viaja con el contenido y se reenvía en futuros Checks.

5 · Arquitectura en movimiento

Así fluye un Check: cliente → aclserver → (fan-out) → Spanner → respuesta.
